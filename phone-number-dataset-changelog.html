Versioning policy

A date-based version changes when a record, safety classification, schema or published expectation changes. Wording and visual fixes that do not change the fixture contract may update a page without changing the dataset version. Consumers should pin a version for deterministic tests and review diffs before accepting an update.

Corrections require an official regulator, numbering administrator, ITU or standards reference. The editorial team does not change a national rule solely because an unsourced directory displays a different example.

Compatibility checklist for consumers

Before adopting a new dataset version, compare added and removed records, calling-code changes, national-length changes, safety-label changes and JSON Schema differences. A wording-only edit should not alter a test snapshot. A changed E.164 example or normalization rule should trigger the affected country suite and a deliberate review.

Applications that embed the CSV should also check column order and encoding. Applications using JSON should validate against the published schema rather than assuming every future field is mandatory. The zero-dependency package exposes the same records, so package, JSON and CSV consumers can compare one canonical fixture contract.

What the changelog does not claim

This page is an editorial history of GetPhoneNum, not an official record of national numbering-plan changes. A regulator remains authoritative for its plan. The log shows when this project reviewed or changed its representation, which source supported that decision and which tests should be revisited.

Repository commits provide the file-level diff, while this page explains the user-visible effect. Keeping both prevents a large generated diff from hiding the reason for a change.

How to report a correction

Use the public project contact channel and include the affected ISO country, current field, proposed field, source URL and why the source applies. Do not submit a real subscriber number as evidence. Security or privacy-sensitive reports should contain only the minimum information required to arrange a safer follow-up.

Reproduce the work

Download the versioned JSON and CSV dataset, inspect the source notes, and report a correction through the public project contact page.
